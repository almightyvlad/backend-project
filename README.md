# Backend Project

REST API на NestJS для управления пользователями с аутентификацией на основе JWT.

## Технологии

- **NestJS** — серверный фреймворк.
- **TypeScript** — язык разработки.
- **PostgreSQL** — реляционная база данных.
- **Kysely** — типизированный SQL query builder.
- **Docker Compose** — запуск базы данных.
- **JWT** — аутентификация и авторизация.
- **Vitest** — запуск тестов.
- **Zod** — валидация переменных окружения.

## Возможности

- Регистрация пользователей.
- Вход и выход из системы.
- Access и refresh tokens с ротацией refresh-токенов.
- Получение профиля текущего пользователя.
- Получение списка пользователей с пагинацией и поиском по логину.
- Обновление и мягкое удаление пользователей.
- Валидация входных данных и централизованная обработка ошибок.
- Документация API через Swagger.

## Требования

Перед запуском установите:

- Node.js и npm.
- Docker с поддержкой Docker Compose.
- Git.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/almightyvlad/backend-project.git
cd backend-project
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Настройка переменных окружения

Создайте файл `.env` на основе примера:

```bash
cp .env.example .env
```

Заполните необходимые переменные окружения. Используйте собственные значения для паролей и секретов JWT. Не публикуйте файл `.env` в репозитории.

### 4. Запуск PostgreSQL

```bash
docker compose up -d
```

Проверить состояние контейнера можно командой:

```bash
docker compose ps
```

### 5. Применение миграций

Схема базы данных создаётся и изменяется с помощью миграций Kysely. Перед запуском приложения примените миграции предусмотренной в проекте командой.

### 6. Запуск приложения

```bash
npm run start:dev
```

### 7. Документация API

После запуска приложения документация Swagger доступна по адресу:

http://localhost:3000/api

## Структура проекта

```text
src/
├── auth/                  # Аутентификация и авторизация
├── common/                # Общие компоненты приложения
├── configs/               # Конфигурация и валидация окружения
├── databases/             # Подключение к БД и миграции
└── features/
    ├── profile/           # Работа с профилем
    ├── refresh-tokens/    # Работа с refresh-токенами
    └── users/             # Работа с пользователями
```

## Безопасность

- Пароли хранятся в виде хешей.
- Access и refresh tokens используют разные секреты.
- Refresh-токены хранятся на сервере в виде хешей и ротируются при обновлении.
- Выход из системы отзывает refresh-токен.
